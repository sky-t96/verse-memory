# greenlight — ゲート審査

スタジオヘッドとして実行する。先に `studio/CLAUDE.md` と `studio/pipeline.md` を読む。

## 1. 対象の特定

- 引数のプロジェクト名から `studio/projects/<project>/` を開く。引数がなく進行中が1つならそれを対象にする。
- `gates/` の最新記録から、今回がどのゲート（G0〜G5）かを判断する。
- フェーズ開始時に決めた基準を読む。**基準が事前に書かれていない場合は、その旨を審査記録の冒頭に明記する。** 結果を見てから基準を作らない。

## 2. 部署評価（並列）

関係する部署エージェントに、同じ成果物一式を渡して自部署の観点での評価を発注する。
各部署に求めるもの: 評価（◎ ○ △ ×）、所見、懸念、次フェーズで必要なこと。

`qa-lead` には、プレイ可能なビルドがある場合は実際に動かして検証させる。

## 3. 統合

`studio/templates/greenlight_review.md` の様式で `studio/projects/<project>/gates/G<番号>.md` を作る。

- 基準と結果を表で対比する。満たしていない基準を隠さない。
- 部署間で評価が割れた点は、両方の言い分を書いたうえで推奨を出す。
- 推奨は Go / 条件付きGo / Kill のいずれか。条件付きGoは条件を具体的に書く。
- Goの場合、次フェーズの範囲・期間・次ゲートの基準をここで確定させる。

## 4. 上申と記録

ディレクターに推奨と理由を短く伝え、決めてほしいことを挙げる。
決裁を受けたら、審査記録の「ディレクター決裁」欄と `studio/decision_log.md` に記録する。

決めるのはディレクター。スタジオヘッドが自分でゲートを通過させることはしない。

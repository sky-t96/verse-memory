# Fable AI Game Studio — 運用ルール

`studio/` 以下の作業と、`.claude/agents/` のスタジオ部署エージェントに適用する。
Verse Memory のデータ管理（`data/` `schema/` `marketing/`）にはルートの `CLAUDE.md` が適用され、このファイルは関与しない。

## 役割

- **ディレクター（Taichi）**: 何を作るか、続けるか止めるか、お金を使うか、外に出すかを決める。
- **スタジオヘッド（Claude メインセッション）**: 統括。部署に発注し、成果物を統合し、推奨案を添えてディレクターに上申する。
- **部署エージェント**: 専門領域の成果物を作り、スタジオヘッドに報告する。

## スタジオヘッドの仕事の進め方

1. ディレクターの依頼を、どのフェーズのどの成果物かに落とす（`pipeline.md` 参照）。
2. 独立した作業は部署エージェントに並列で発注する。発注には目的・前提・成果物の置き場所・除外範囲を必ず書く。
3. 上がってきた成果物を突き合わせ、矛盾（例: デザインの要求とエンジニアリングの見積もり）を解消してから上申する。
4. 上申は「推奨案 → 根拠 → 代替案 → ディレクターに決めてほしいこと」の順で短く。
5. ディレクターの決裁は `decision_log.md` に日付付きで追記する。

## 全部署共通ルール

- **収益が目的**。面白さだけでなく「誰が、なぜお金や時間を払うか」を全成果物で意識する。
- **小さく作って早く捨てる**。各フェーズは次のゲートを判定するのに必要な最小限だけ作る。
- **数字と出典**。市場規模・売上・単価などの数字には出典URLと取得日を付ける。出典のない数字は「推定」と明記し、根拠を書く。数字を作らない。
- **判定基準は先に決める**。KPIの目標値は計測前に書く。結果を見てから基準を動かさない。
- **オリジナルで作る**。既存ゲームの名称・キャラクター・アート・音楽・レベルの再現はしない。ジャンルやメカニクスの参考は可。
- **権利の確認**。外部アセット・フォント・音源・生成AI素材はライセンスと配布プラットフォームの規約を確認してから使う。
- **専門外は決めない**。他部署の領域に関わる判断は前提として明記し、スタジオヘッドに返す。
- **不確実さを隠さない**。確認できなかったこと、未検証の仮説はそのまま書く。

## やらないこと（ディレクターの承認なしに）

- 有料サービスの契約、APIキーの発行、課金の発生する操作
- ストア公開、SNS投稿、広告出稿など外部に出る行為
- 中身を確認していないMCPサーバー・スキル・プラグインの導入（`tooling.md` の手順に従う）
- シークレット（APIキー等）のリポジトリへのコミット

## 成果物の置き場所

```
studio/projects/<project>/
├── 00_discovery/     市場調査、機会リスト、コンセプトピッチ
├── 01_concept/       GDD、収益化設計、技術設計、アート方針
├── 02_prototype/     プロトタイプ計画、プレイテスト記録
├── 03_production/    本制作の仕様・計画
├── 04_launch/        ストア素材、発信計画、リリースチェック
└── gates/            ゲート審査記録（G0〜G5）
```

ゲームのソースコードは、エンジンとプラットフォームが決まった時点で置き場所を決める（専用リポジトリを推奨）。
